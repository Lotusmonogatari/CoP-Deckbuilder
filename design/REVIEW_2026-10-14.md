# Mechanics and assets review (2026-10-14)

Method: full GUT suite (1071/1071 pass), `tools/verify.sh` (green on the last merge), a full bot playthrough (PC03), bot stage trials on 21 rooms (20 fights each, PC02), data and asset scans over `data/*.json` and `assets/`, and two read-only code reviews (rules layer; UI, save and audio). **Reading-only findings from the code reviews were not reproduced by running anything**; each is marked.

## Executive summary

| Area | State | Biggest issue |
|---|---|---|
| Rules and tests | Sound | 1071 tests pass; the bot finished 80 level attempts with no invariant violations. A few edge bugs in the engine (below) |
| Content volume | Strong | Every room clears the 3x rule; every bill has a room, a visitor and laws |
| Content quality | Repetitive | Opponent cues are 27% unique lines; transitions 56% |
| Balance | Uneven | Most rooms are 100% for a geared bot; ST08, ST18 (PC02) and ST19 are 0%; Town Hall 30% |
| Art | **Largely missing** | Opponents 3 of 125 drawn; staff, visitors, card art 0; PC02 and PC03 have no portraits at all |
| Audio | **None** | Every sound entry is wired and empty |
| Save and resume | Fragile | A corrupt save is silently replaced; no migration; stale IDs not checked |
| Mobile | Unproven | No Android/iOS export has been run (M6 not started); layout verified only in headless matrix tests |

## 5. UI, save and audio findings (code read)

| # | Severity | Where | Issue |
|---|---|---|---|
| U1 | **High** | Battle, Visitor and Floor Vote screens | If a stage cannot start (empty config or setup failure) the screen shows a message and disables the controls; there is no way out, and Resume loads the same screen |
| U2 | **High** | `SaveManager`, `IntroScreen` | A corrupt save, or one from a newer build, is replaced by a new game with no message and no backup; a newer-build save disables saving for the session |
| U3 | Medium | `SaveManager` ~61 | A failed or truncated write can replace the last good save |
| U4 | Medium | `GameState.load_save` | No migration and no check that saved IDs (cards, items, levels, staff) still exist; the workbook is renumbered often (the Shop was) |
| U5 | Medium | Many scripts | About 20 player-visible strings are typed in scripts ("Deck %d · Hand %d", "free", "standing %d", "Against %s", fallbacks such as "A stage"); the Floor Vote screen shows raw setup problems |
| U6 | Medium | Theme | Several base fonts are 24 to 26 px; Text size Small (90%) takes them to about 22. Card plate text colour is roughly 4:1 contrast |
| U7 | Low-medium | `CueBanner`, `StageTransitionScreen` | Tweens are never killed, so tapping to skip mid-slide can leave the band mis-positioned |
| U8 | Low-medium | `Overlay` | A tap in the 40 px margin outside a panel closes it; an edge swipe can dismiss a shop panel |
| U9 | Low | Office rows | Fixed 620 px labels beside 120 px icons may crowd at Large text |
| U10 | Low | Resume | Resuming a level skips the Level Intro lean choice and any pending transition |
| U11 | Low | Scenes | Standalone scenes call `get_tree().quit()`; iOS discourages this (only reachable outside a level) |
| U12 | Info | Text | The exporter calls `office.trigger.*` "unused" because they are built from variables; a removed row would show a raw key. `party_opinion.helping/hurting` are dead rows |
| U13 | Info | Audio | No defects; every sound name used exists; `play_music` restarts the same track on each scene reload (not verified) |

## 6. Recommended order

1. **Art triage**: PC02 and PC03 portraits (half the playable cast), then the opponents who appear most (Town Hall pool, committee MPs), then card art. Pick one portrait size.
2. **Safety**: an exit from a stage that cannot start (U1); keep a `.bak` of the save, verify the write, tell the player when a save is unreadable, and drop saved IDs that no longer exist (U2 to U4).
3. **Balance**: decide ST08 (it looks unwinnable), the Cabinet (ST18) and the Caucus; lift the 100% rooms or accept them as breathers; look at Appeal and the Earnest bias.
4. **Engine**: R1 to R3 each get a test and a fix; the rest are cheap.
5. **Content**: backing modifiers for BO17 to BO30; more opponent cue lines; time-word and ticker-length pass.
6. **Text**: move the typed strings (U5) into the Text tab.
7. **Mobile**: a first real Android build and a notched-phone pass (the dynamic-screens plan's step 6).

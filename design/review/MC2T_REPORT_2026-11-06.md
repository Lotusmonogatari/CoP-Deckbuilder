# MC²T report: Coliseum of Parliament (expert pass, no participants)

*2026-11-06. Draft for Cameron. Protocol: `design/reference/MC2T_PROTOCOL.md`. Everything here comes from code, data and an automated screen walk; **nothing here is player evidence**. Scores marked "est." are expert estimates that human tests must confirm or overturn.*

## 1. Executive summary

| Question | Answer |
|---|---|
| What was run | Keyword audit (K1), touch-target audit on 21 real screens (405 controls), expert heuristic pass, card-rule ground truth |
| What was not run | Everything needing people: freeze probes, predict-then-reveal, term definitions, mis-tap counting, diary. The kit for them is ready |
| Provisional verdict | **Black (fail) on gates, driven by two mobile criteria**, not by the rules or text |
| Gate 1: MO1 touch targets ★ | **Fails on the spec audit.** 93% of tappable controls are under the iOS 44 pt minimum; the standard button is about 34 dp (5.7 mm). Mis-tap rate still unmeasured |
| Gate 2: MO5 interruptibility ★ | **Fails on code reading.** Nothing saves between the start and the end of a stage, so a phone call or app switch mid-stage can lose it. A real-phone test must confirm |
| Gate 3: MO7 monetization ★ | Not applicable (no real-money purchases). Weight redistributed |
| Strengths | Intent shown a turn ahead; pile counts present; drag-to-play with a cancel; card preview; fixed vocabulary mostly held (0 forbidden terms on screen except a developer-only string) |
| Cheapest big win | Taller buttons (about 126 to 144 base px). One layout decision, no rules change |

## 3. Findings

Severity is the protocol's Nielsen 0 to 4. "Prov." = provisional until a human test.

| ID | Finding | Evidence | Sev. (prov.) | Proposed fix (Cameron decides) |
|---|---|---|---|---|
| M1 | Buttons are below the platform minimums | 378 of 405 targets under 44 pt; default button 90 px (about 34 dp); battle Details and Inventory buttons 75 px (about 29 dp); deck screen 80 px | **4 if the mis-tap rate exceeds 10%, else 3** | Raise the default button to about 126 px (iOS 44 pt) or 144 px (Material on a 360 dp phone); give list rows the same minimum; keep 8 dp spacing |
| M2 | A stage is not saved mid-way | `BattleScreen.gd` line 300: "nothing is saved until the stage is finished" | **3 to 4** (a stage that is lost counts as lost progress) | A per-turn stage snapshot restored on launch, with a "you were mid-debate" reminder. More than 150 lines: needs an outline and your "go" |
| L1 | **"Boosters" names two things.** The Office button into the backing shop reads "Boosters" (`office.backing`), while everywhere else the perk is a "backing"; "Boosters" is also the audience group SG04 on cards ("for every N Boosters") | `design/review/MC2T_LEXICON_2026-11-06.md` §2 | 3 | Rename the button to "Backings" (one Text row). Segment name stays |
| L2 | Several words for how an organization feels about you: standing (31 lines), favorability (11), goodwill (3), "approval among" (staff reward) | Lexicon §2 | 2 | Keep "standing"; reword the 3 goodwill and the approval lines. "Favorability" is also a bar unit, so check before changing |
| L3 | "Support" has at least four meanings: the stage bar's unit, Constituency support, Party support, and "supporters" | Lexicon §3: 62 lines | 2 | Already fixed terms for the meta numbers; ensure the bar always reads "support" with its stage unit label |
| L4 | Two discard phrasings: "Discard 1 other card." (a cost taken as part of the effect, 8 cards) and "Discard 1 other card to play." (a condition of playing, 8 cards) | Data and `BattleEngine.discard_required` | 2 | Make the first read "Discard 1 other card first." or give both a shared icon; test against first-read comprehension |
| L5 | "Round" appears only in the Trade screen caption; "fight" appears four times; "room", "stage", "level" all name play units (24, 46, 77 lines) | Lexicon §2 | 1 | INFORMATION_STANDARDS fixes "level and stage"; consider adding "room" to that list |
| R1 | A card with base 1 on a 0.5 room shows 1, not 0.5 (round half up), so the suppression is invisible on low numbers | Ground truth P2 and P6 in the kit | 2 | Show the multiplier on the card ("x0.5") or document the rounding in How to Play |
| R2 | Guard, Draw and Gaffe are never scaled by rooms or questions, but only the How to Play page says so | `how_to_play.json` line 217 | 1 | None needed if the test shows players read it |
| T1 | The Details panel lists the piles inside the "Room rules" toggle | `BattleScreen._rules_lines` | 2 | A small deck, hand and discard count on the main battle screen |
| F1 | No first-battle tutorial; How to Play is a separate page | No tutorial code; MO6 | 3 | A guided first stage (content built like the nearest level; needs an outline) |

Not defects: `No turn limit`, `Tier N` for cards and levels (distinct from Staff Rank), and `This modifier has no ID` (a developer error string, never shown to players).

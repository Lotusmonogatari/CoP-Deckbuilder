# P13 plan: Office screens (draft for Cameron, 2026-11-20)

Branch: `panel/p13-office-screens`, from `main` at `11c8b68`. Presentation only: no rules, numbers, IDs, schema or canon change. This plan is more than 150 lines of new code, so nothing is built until you say "Go".

## 1. Executive summary

| Question | Answer |
|---|---|
| What changes | Six Office screens (Reputation and Results with its factors pop-up, Marketplace, Office Management, Events, Administration) move onto one shared frame, in all three styles. |
| Key finding | Today each of these is an `Overlay` pop-up panel (`_xxx_panel.open(title, rows)`). `Overlay` is what guarantees a Back button, the escape key and a tap-outside exit on every screen. The frame must **sit inside `Overlay`**, not replace it, so no screen can ever trap the player. |
| Shape | One reusable `OfficeScreenFrame` (chips, title, tabs, scrolling body, optional fixed footer), drawn per style by a `OfficeFrameStyles` palette (the pattern of P12's `LevelBriefingStyles`). Each screen gets a small pure "rows" class that turns today's GameState reads into plain dictionaries; the frame only draws them. |
| New rules code | Only reads. One small reader for the Events "Coming up" tab (dated events later in the week) in `EventEngine`, with a test. No number or rule changes. |
| Size | About 6 commits plus setup and finish. Each commit ends with `tools/verify.sh` green. |
| Your review points | Text rows (section 5), the Resign box position (section 4), and screenshots after Administration (before the frame is reused four more times). |

## 2. The shared frame

| Part | How it is built |
|---|---|
| Host | `OfficeScreenFrame` is a Control placed as the body of an `Overlay` (new option on `Overlay`: `frame_mode`, which hides its plain title and puts its Back button in the frame's top-left as "‹ Office"). Back, escape and tap-outside stay exactly as today. |
| Top bar | "‹ Office" (at least the game's minimum touch size, `UiKit` wins over the mockup's 44 px) and status chips on the right. |
| Title | Display font from the style tokens, with the Japanese subtitle small and muted beside it. |
| Tabs | Optional row, scrolls sideways. Tabs only map to sections that exist. |
| Body | One scrolling column of cards. Top bar, title and tabs stay fixed. |
| Footer | Optional fixed primary button (Office Management only). |
| Per-style drawing | `OfficeFrameStyles` reads `UiStyle` tokens (colour, font, radius, border, slant) and draws card, tab, chip and button looks: Woodblock (paper, ink border, red offset shadow), Living Office (rounded, soft), Broadcast (navy, gold rules, slanted tabs and button). Spec section 3 gives the values; where a token already exists in the UI Styles tab I use it, and any missing one is added as a UI Styles row (no schema change). |

## 6. Tests I will add

| Test | Checks |
|---|---|
| Equivalence, per screen | The values the new view receives equal what today's panel shows (standings and changes, prices and refusals, staff ranks and wages, event costs, hours and refusals, settings states). |
| No `because` in lists | No list row contains `record.because` text; tapping a change button opens the factors pop-up with the same rows `_open_factors` builds today. |
| Staff count | The summary count equals the number of person cards, in every role. |
| Events | Only events arrangeable at the current office are listed; a dated event is a banner with no Arrange button. |
| Frame safety | Every frame screen still closes by its Back, escape and tap-outside. |
| Coming up reader | Dated events later in the week are listed in date order; done ones are not. |

## 7. Test impact (the biggest risk)

40 test files mention `OfficeScreen`; the click tests find controls by node name (`find_child`) and by button text. The Office screens named in the specs are touched by: `office_menus_driver`, `resign_hold_test`, `market_tabs_test` and driver, `shop_items_driver`, `inventory_driver`, `new_game_driver`, `cosmetics_driver`, `how_to_play_driver`, `image_pan_driver`, `mash_driver`, `promises_placement_test`, `hosted_driver`, plus unit tests `test_funds_limit`, `test_inventory`, `test_week_end_preview`, `test_report_pieces`, `test_resign`, `test_resign_hold`.

My rule: **keep every existing node name and button text** (`RaisePressureButton`, `PersonalTab`, `OfficeTab`, `StylesTab`, `Arrange_<id>`, `MarketFunds`, `AdministrationButton` and so on). Where a layout change forces a test to change, I change it on purpose and name it in the report.

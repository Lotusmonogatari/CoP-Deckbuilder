# Workplan: items with a number of uses (draft for Cameron)

Nothing here is built. Today every item is a one-shot: one use removes one copy. The request: an item can have **a number of uses**, the uses are **tracked** and shown, and the item is **disposed of** when they run out (for example a Paper Shredder good for 5 days, a box of Commendation Cards good for 10 cards).

## 1. How items work today

| Piece | Today |
|---|---|
| Inventory | `inventory` is `{ item_id: count }`: copies, nothing about wear |
| A use | Calls `_take_item(item_id)` (one copy gone). It is called from the Office use, the stage use, the staff screen's confirm (person and Office items), a promise that hands an item over (`promises`), and event or visitor choices that cost an item |
| Limits | `Stack Cap` (most copies held) and `Purchase Limit` (most buys) on the Shop tab |
| Shown | Inventory panel and Marketplace show a count; the staff screen shows "n left" |

The central function is `_take_item`, so one door controls how items disappear. That makes this change small compared with its reach.

## 2. The design

### 2.1 The rule

| Rule | Detail |
|---|---|
| **Uses** | A new Shop column **Uses** (a whole number; blank means 1, which is exactly today's behavior). A bought copy starts with that many uses. |
| **A use** | One *use* takes one use off one copy. When a copy reaches 0 uses it is **disposed of** (removed) and the player is told. |
| **Handing an item over** | A promise, gift or event that gives an item away removes the **whole copy** regardless of its uses left (you cannot give half a shredder). Only a *use* spends one use. |
| **Which copy is used first** | The copy with the **fewest uses left**, so partly used items are finished before a fresh one is opened. |
| **Buying more** | Each bought copy is a new item with full uses. Stack Cap and Purchase Limit still count copies. |
| **Existing items** | Blank Uses = 1, so nothing changes until a row is edited. |

### 2.2 What counts as one use, per kind of item

| Item | One use is | Example |
|---|---|---|
| Staff item in a person's box (coffee, tea, Commendation Cards, Duplicate Pad) | A confirmed day it was placed in | Commendation Cards, 10 uses: ten confirmed days |
| Office box item (Official Seal, Stacking Tray, Paper Shredder, Kaiju-sized items) | A confirmed day it was placed in | Paper Shredder, 5 uses: five days |
| A gift | The whole copy (as now) | Unchanged |
| Battle and Office consumables | One use as now; a Uses number above 1 gives a multi-use version | A thermos good for 3 stages |

### 2.3 What the player sees

| Where | Display |
|---|---|
| Marketplace | The price row says "5 uses" |
| Inventory panel | Each held item: "Paper Shredder: 3 of 5 uses left" (several copies: "2 copies: 3 and 5 uses left") |
| Staff screen item cards | "· 3 uses left" instead of "· 2 left" for a multi-use item |
| Item popup | "Uses left: 3 of 5. It is thrown away when they run out." |
| When one runs out | A line in the day's report and on the Office ticker: "Your Paper Shredder wore out and was thrown away." |
| Confirm button | No change; the projection already lists what the day does |

### 2.4 Optional later: wear by time, not by use

A second column `Lasts` (days) would let an item expire on its own after N days even if unused (a newspaper subscription). It is not in this plan; say so if you want it.

## 3. How it fits the code

| Piece | Where | Size (estimate) |
|---|---|---|
| Pure rules: spend a use, pick the copy, report disposal | New `scripts/rules/ItemUses.gd`, no UI | About 80 lines |
| Run state: per-copy uses | `GameState.item_uses`: `{ item_id: [uses_left, ...] }`, one entry per copy, kept in step with `inventory`; `item_count` unchanged | About 80 lines |
| The doors | New `_spend_use(item_id)` for uses; `_take_item` (whole copy) stays for giving away; the staff confirm and the Office and stage use paths call `_spend_use` | About 60 lines |
| Save and load | `item_uses` joins the saved fields; an older save with only `inventory` gets full uses for every copy | About 30 lines |
| Data | Shop column `Uses` (optional, blank = 1), exporter check (a whole number from 1 up) | About 20 lines |
| UI | Inventory panel lines, Marketplace row, staff item card caption and popup, report line, ticker line; about 12 Text rows | About 120 lines |
| Tests | Spend, order of copies, disposal, save round trip, old-save migration, UI strings | About 150 lines |
| Content | Set Uses on the new office items (suggested below) | Workbook only |

About 400 lines of code plus tests, so it is built in phases, each with its own "Go".

## 4. Phases

| Phase | What | Result |
|---|---|---|
| 1. Rules and data | `ItemUses.gd`, the Uses column, exporter check | The numbers and the rules exist and are tested; nothing visible |
| 2. Run state | `item_uses`, `_spend_use`, save and load, old-save migration | Items can wear out |
| 3. Staff screen | Staff and Office items spend a use on a confirmed day; cards and popup show uses | The five new items work as durable items |
| 4. Everywhere else | Inventory panel, Marketplace, report and ticker lines | Uses visible everywhere |
| 5. Content | Uses set on items (suggestions below) | Playable |

## 5. Suggested uses for the five new items (draft)

| Item | Uses | Why |
|---|---|---|
| Commendation Cards | 10 | A box of cards goes a long way |
| Duplicate Pad | 5 | A pad runs out |
| Official Seal | 8 | Lasts; the strongest, so priced higher |
| Stacking Tray | 12 | A tray does not wear out quickly |
| Paper Shredder | 5 | Needs replacing |
| Kaiju-sized coffee, tea | 1 | As now, one use |

Prices would be set per use so a 10-use item costs more than a 1-use item (a Balance row for the price per use is one option).

## 6. Risks

| Risk | Handling |
|---|---|
| Inventory and uses fall out of step | `item_count` is derived from the copies; a test checks they always match; on load any mismatch is repaired |
| Players cannot tell a used copy from a fresh one | The uses-left line is on every screen that shows the item |
| Durable items trivialize the economy (buy once, use forever) | Each item has a finite Uses number, and uses are only spent on confirmed days |
| Old saves | A missing `item_uses` becomes full uses for every held copy |

## 7. Decisions for Cameron

1. **Spend order:** finish the most-used copy first (proposed), or the newest?
2. **Whole copy when handed over:** a gift or promise removes the whole copy, whatever its uses left (proposed)?
3. **Wear by time:** leave out (proposed) or add a `Lasts` days column now?
4. **Price:** each item priced on its own (proposed), or a Balance price per use?
5. **Should battle consumables get multi-use versions too**, or only staff items for now (proposed)?

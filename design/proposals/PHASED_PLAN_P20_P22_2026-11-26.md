## 1. What I checked in P22

| Item | Finding |
|---|---|
| Fonts | Shippori Mincho B1 (Regular and Bold) is already in `assets/fonts/`, as is Antaka Brush Text for the ō, ū, ā, ī fallback. Nothing to add. |
| Art | 12 SVGs (8 banners, 2 emblems, 2 vans), 333 to 1,900 bytes each. None uses filters, masks, patterns, text or gradients, so Godot imports them cleanly. The banner texture (fibers or stone) is a token, so it is drawn by code. |
| Tokens | Concrete: 29 colours, one font, 3 type, 1 shape and 4 art rows per skin, "anything else from woodblock". The exporter check is straightforward. |
| **One style for the whole game today** | `UiStyle.current()` is a single global; screens read it while they are built, and the theme overlay is merged into the project theme. P22 needs a skin that covers only the campaign screens. That means a scoped override (set while a campaign screen is built and shown, cleared after) plus a Theme applied to that screen's root, not the project theme. This is the one real engineering step in P22. |
| The player must not pick the skins | The two campaign styles must stay out of `UiStyles.ALL`, the New Game strip and the Office styles tab. They are known to the exporter but not selectable. |
| Banner wording | The P20 content file has the phase names but **no banner sentences, kickers or button labels**. Those exist only in the mockup generator (`gen_campaign.py`), with the first cycle's dates and "seven weeks" typed in. They need placeholders ({date}, {weeks}, and the action limit and sprint numbers from Balance). The wording belongs in P20B (where the banners are built), so P22 only reskins. |
| Cycles after the first | The Banners text says "make your case to the Candidate Selection Committee". That is wrong for the cycle you step aside from (EC03). It needs its own wording, or no banner. |
| "The Prime Minister speaks" | A kicker in the Banners banner. It is a statement about who calls the election. It is yours to confirm (canon). |
| Phase bar note | "34 days to the campaign · ×1.5" needs a rule: days until the next phase. It belongs with the phase bar in P20B (`ElectionCycle`), not P22. |
| Tier numerals | Roman numerals (0, I, II) for the Gladiator. Tiny pure function (`CampaignSkin.roman`). |
| Checks | The prompt asks for 20 screenshots. The text sweep and the click tests should also cover the skinned screens, otherwise the text-size and aspect checks miss them. |

## 4. Risks and how the plan handles them

| Risk | Handling |
|---|---|
| The scoped skin leaks into popups built later | P22a prototypes it on one card first, with a test that builds a skinned screen and a plain one in the same session. |
| Selection thresholds end the run | Checkpoint 4 uses the bot before anything else depends on it. |
| Decay numbers do not stop the meters reaching 100 | Checkpoint 5 measures it, as agreed. |
| Text sweep and aspect tests miss the skinned screens | P22c adds them. |
| A very long chain of unmerged branches | Each phase merges on your "merge" before the next starts, so no branch sits on another. |

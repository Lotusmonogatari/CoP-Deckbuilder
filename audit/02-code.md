## The good news first

The code is in better shape than most projects at this stage. These came back clean:

- **Typing:** all 1,691 functions declare a return type; only 9 local variables are untyped.
- **TODO/FIXME/HACK:** none in `scripts/`.
- **Dead code:** no unused script; no function that nothing references. 24 functions are referenced only by tests (C-12).
- **Signals:** the 8 `EventBus` signals each have exactly one listener (`Audio.gd:128-136`) and 1-2 emitters; none orphaned, none doubly connected.
- **Freed-node access after `await`:** only 4 awaits exist, and each re-checks with `is_instance_valid` (`OpponentPresenter.gd:255-258`, `PlayerPortraitPresenter.gd:111-115`, `MessagePresenter.gd:83-90,108`).
- **Save writes:** written to a temp file, verified, backed up, then renamed (`SaveManager.gd:141-163`); an unreadable save falls back to its `.bak`; a save from a newer build is left alone.

## Things I looked for and did not find

- **Race on scene change / double taps:** a dedicated click test (`tests/interaction/mash_driver.gd`) hammers the same control and checks for exactly one effect; handlers are synchronous. Not re-run in this audit.
- **Missing awaits:** none found; the code avoids coroutines almost entirely.
- **Cheats or debug switches left on:** `data/rules.json` has `open_card_collection: false` and `level_gating_enabled: true`. The one debug-only branch is guarded (`BattleScreen.gd:659`, `OS.is_debug_build()`). `data/playtest_level.json` and `data/playtest_cards.json` are loaded at start (`DataDB.gd:41`); the name `for_playtest_stage` is the normal path for every stage, not a cheat.
- **Hard-coded paths:** only `res://` scene constants and four `user://` files. The Office scene path is repeated in three files instead of using `StageRouting.OFFICE_SCENE` (see R-04 in Phase 3).
